# Préférences globales

- Toujours répondre en français.
- Texte en accents graves (`...`, code) entouré d'espaces : remplacer ces espaces par des `&nbsp;` — dans tes réponses et les docs autonomes uniquement. **Pas** dans les fichiers chargés dans mon contexte (CLAUDE.md, CLAUDE.local.md et leurs `guides/`) : y garder des espaces normales.
- Docs `.md` autonomes destinés à l'utilisateur : lus dans l'extension Markdown Viewer (markdown-it, comme VSCode) → utilisables : GFM (blocs ``` avec langue, colorés ; tableaux ; citations `>`), notes de bas de page `[^1]` pour les précisions secondaires (texte de note = phrase rédigée commençant par un mot, pas par `&nbsp;` ni du code ; définitions groupées en fin de fichier), listes de définitions (`terme` puis `:   déf`), `==surligné==`, `H~2~O` / `x^2^`, abréviations, cases `- [ ]`, diagrammes ```mermaid (libellés sur une ligne : `<br>` ignoré, pas d'entités HTML), formules `$…$` / `$$…$$`, emojis Unicode bienvenus pour titres/repères. TOC = panneau latéral auto (pas de marqueur `[TOC]`). Éviter : raccourcis `:emoji:` ; `$` hors code (pris pour une formule → variables PowerShell toujours en code) ; compter sur un retour ligne simple pour couper une ligne (`breaks` désactivé). Syntaxe affichée brute chez l'utilisateur (`[^1]`, `==`, `:` de définition, `[ ]`) → option correspondante non cochée dans les options markdown-it de l'extension, pas une erreur du fichier : le lui dire, ne pas réécrire le doc.
- « CLAUDE.md » (singulier ou pluriel, quel que soit le verbe : relire, mettre à jour, comprimer…) désigne toujours AUSSI le `CLAUDE.local.md` du même dossier : agir sur les deux ensemble, sauf si je nomme explicitement l'un ou l'autre.
- En écrivant/modifiant, router chaque info vers le bon fichier : partagé + versionné → `CLAUDE.md` ; perso, propre à ma machine/mon poste, chemins absolus, ou non destiné au versionnement → `CLAUDE.local.md`. Ne pas dupliquer entre les deux. Priorité sur ce routage : le `CLAUDE.md` doit rester compréhensible seul, sans le `CLAUDE.local.md` — ne pas y déporter une info nécessaire à sa compréhension.
- `~/.claude/README.md` : doc destinée à l'utilisateur (humain), pas au modèle ; non chargée dans le contexte (gratuite en tokens). Y router ce qui ne sert qu'à l'utilisateur : techniques d'usage de Claude, rappels d'habitudes, mémos token — surtout ce que l'utilisateur seul exécute (ex. `/clear`). Distinction au jour le jour : instruction au modèle sur son comportement → `CLAUDE.md` ; conseil/rappel à l'utilisateur → `README.md`. Ne pas dupliquer.
- Économiser les tokens de contexte : éviter de lire un fichier entier quand seule une portion compte (demander une plage de lignes) ; préférer Grep/Glob ciblés à des recherches larges renvoyant des pavés de contenu. Pour une exploration large (plusieurs fichiers, portée floue) où ça fait vraiment gagner des tokens, passer par un subagent Explore plutôt que de le faire soi-même — pas systématique : ne pas l'invoquer pour une recherche déjà ciblée ou triviale, où le coût de délégation dépasserait le gain.
- Si je lance `/compact` alors que ce serait contre-productif niveau tokens (ex. contexte déjà petit, résumé qui coûterait plus qu'il ne ferait gagner), me le signaler avant d'exécuter plutôt que de compacter sans réagir.
- **Inadéquation modèle/effort = arrêt, pas une remarque en passant.** Si ma demande semble clairement nécessiter un modèle/effort plus puissant que l'actif, OU au contraire triviale pour l'actif (surdimensionné) : le signaler **avant tout autre travail**, conseiller le modèle et l'effort adaptés, puis **s'arrêter — ne pas répondre à la demande, ne rien commencer** tant que je n'ai pas changé de config ou dit explicitement de répondre quand même. Poser la question via `AskUserQuestion` (options : garder la config actuelle / je change puis relance). Ne jamais contourner en signalant *et* répondant dans la foulée, même si la réponse paraît courte.

# Pièges techniques

- **pnpm : jamais de chemin interne codé en dur** (service, tâche planifiée, raccourci, script, config) — ni `pnpm/global/v<N>/<id>/…` (install isolée par paquet global, recréée à chaque `pnpm add -g` / màj → chemin cassé sans erreur visible), ni `node_modules/.pnpm/<pkg>@<ver>…`. À la place : outil global → lanceur stable dans `pnpm bin -g` (shim réécrit par pnpm à chaque màj) ; dans un projet → dépendance locale + script `package.json` / `pnpm exec` / `node_modules/.bin`, ou `require.resolve()` en code.
